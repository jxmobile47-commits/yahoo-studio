================================================================================
PHASE 1: AUTOMATED COLLECTION (Weeks 1-4) - Target: 20,000 samples
================================================================================

SOURCE 1: Web Scraping (5,000 samples)
---------------------------------------
Target: Ultimate Guitar, Chordie, E-Chords
Method: Automated scraping with rate limiting
Pros: Real user chord annotations
Cons: Timing is approximate, needs audio matching

Run:
  cd python_backend/scripts/data_collection
  python scrape_chord_websites.py --max-songs 5000 --output data/scraped_chords

Then match with audio:
  - Download audio from Spotify/Apple Music APIs (if licensed)
  - Or use YouTube audio downloader
  - Or skip audio, use synthetic matching

SOURCE 2: YouTube + Chord Matching (5,000 samples)
---------------------------------------------------
Target: Popular songs with known chord progressions
Method: Download audio, match with scraped/known chords

Run:
  python youtube_collector.py \
    --playlist "PL..." \
    --chords-file chords.json \
    --output data/training

Playlists to target:
  - "Top 1000 Songs of All Time"
  - "Greatest Guitar Songs"
  - "Billboard Hot 100 (by year)"

SOURCE 3: Public Datasets (10,000 samples)
------------------------------------------
Available datasets:
  1. McGill Billboard Dataset (~700 songs, high quality)
     https://mcgillbillboard.s3.amazonaws.com/
     Format: .lab files with precise timestamps

  2. Isophonics Dataset (Beatles, Queen, etc.)
     http://isophonics.net/datasets
     ~300 songs, expert annotations

  3. CASD - Chord and Scale Dataset
     ~2,500 songs

  4. Rock Corpus
     ~200 songs, detailed annotations

  5. Lakh MIDI Dataset (~100,000 MIDI files)
     http://colinraffel.com/projects/lmd/
     Can synthesize to audio

  6. Wikifonia (MusicXML lead sheets)
     Can synthesize MIDI

Run:
  python public_datasets.py --output data/training

================================================================================
PHASE 2: SYNTHETIC DATA (Weeks 2-3) - Target: 30,000 samples
================================================================================

WHY SYNTHETIC?
  - Unlimited quantity
  - Perfect annotations (ground truth)
  - Full control over chords/keys/tempo
  - Augment real data

HOW:
  1. Generate chord progressions from templates
     - Pop: I-V-vi-IV, I-vi-IV-V
     - Jazz: ii-V-I, circle of fifths
     - Blues: I-IV-V
     - Rock: power chord progressions

  2. Synthesize to audio using MIDI + SoundFont
     - Realistic piano/guitar sounds
     - Add bass, drums for realism

  3. Apply audio augmentation
     - Tempo variation (80-160 BPM)
     - Pitch shift (all 12 keys)
     - Add reverb/background noise
     - Volume variation
     - Clipping simulation

Run:
  python synthetic_generator.py \
    --output data/synthetic \
    --n-samples 30000 \
    --soundfont /path/to/piano.sf2

================================================================================
PHASE 3: USER FEEDBACK LOOP (Ongoing) - Target: +10,000/month
================================================================================

CROWDSOURCING STRATEGY:
  1. Launch "Chord Challenge" feature
     - User hears audio, guesses chord
     - Earn points for correct answers
     - Leaderboard for top contributors

  2. "Correct This Chord" button
     - User clicks wrong chord in output
     - Submits correction
     - Gets instant feedback

  3. Verification system
     - Multiple users must agree
     - 3+ agreements = verified
     - Weighted by user reputation

  4. Active Learning prioritization
     - Model identifies uncertain predictions
     - Shows these to users first
     - Maximizes value of each correction

IMPLEMENTATION:
  - SQLite database for corrections
  - REST API for submission/retrieval
  - React component in frontend
  - Gamification (badges, streaks, levels)

Database: user_feedback_system.py
API: feedback_bp (Flask blueprint)

================================================================================
PHASE 4: DATA QUALITY & FILTERING
================================================================================

QUALITY CONTROL:
  1. Low confidence filter
     - Remove samples where model confidence < 0.5
     - Send to user for verification

  2. Duration filter
     - Minimum 30 seconds
     - Maximum 10 minutes

  3. Chord diversity filter
     - Ensure all 170 classes represented
     - Oversample rare chords

  4. Duplicate detection
     - Audio fingerprinting (chromaprint)
     - Remove duplicates

  5. Cross-validation split
     - Artist-level split (prevent leakage)
     - Genre-stratified split
     - 80% train / 10% val / 10% test
